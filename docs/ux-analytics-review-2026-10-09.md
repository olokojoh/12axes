## 先补测量，才能判断优化有没有用

1. **来源被清空。** 当前 GA4 会话中 Direct 为 12,254（76.45%），Organic Search 为 3,493（21.79%）。`app/Analytics.tsx` 明确将 `page_referrer` 设为空，这会损害来源识别；不能解读为真实直访占比或自然流量没有销售。建议在用户同意后只保留经过清洗的外部来源域名/必要渠道信息，继续排除分数、敏感 URL 参数和报告凭证，不恢复完整原始 URL。
2. **建立真正的答题漏斗。** 区分新开始、恢复、分享来访；用仅用于分析的随机测试实例标识及同一次测试的阶段事件连接流程。只记录题量、进度阶段、语言、设备，不记录答案、轴分数或意识形态。中途才同意分析的访问明确标记为中途进入，不能回填成已观察完整测试。36→60 的扩展要保留同一实例关系。
3. **完善付款事件语义。** 保留点击意图，补充 Checkout 创建成功、失败类型、取消返回；各套餐曝光带 plan。错误事件仅使用固定错误分类，不发送响应正文或私人凭证。订单是付款事实依据，GA4 是获同意样本中的行为分析。
4. **购买收入不完整。** 本次 purchase 10/7 为10次、US$74.92；10/8 为14次、US$154.87。客户端依赖同意、原标签页记录和支付后返回，可能漏计；服务端先标记领取、客户端再发 GA，也存在未送达的缺口。收入不是扣手续费、退款、税费后的净收入。按订单账本对账，升级补差价与首次购买分开。
5. **不要用滚动事件暴跌判断用户退出。** 10/8 scroll 仅2次，而前一天649次；最近关闭了 Enhanced Measurement，不能把此变化当成几乎没人往下看。需要自己定义免费结果、分享区和具体套餐的可见事件。
6. **排除测试污染。** 本次未核验 GA4 后台内部流量过滤状态。先确认开发/沙盒访问隔离，生产人工验收采用可识别且不含敏感数据的测试标记；不能根据重复点击直接删掉真实用户。

目前 variant 在代码中固定为 baseline，没有正在运行的随机实验。若验证新布局，应同期开启稳定分组，刷新/语言切换保持分组，分组不写入分享链接；以整体效果为主，语言和设备做分析维度，避免要求每个小格都显著。先排除布局与流程错误，再检验收入、分享和完成的变化；不设置“跑一天一定有答案”的承诺。

## 暂时不支持的结论

- 不能据此判断 4.99、9.99、14.99 哪档该涨价或下架：购买追踪太新，尚缺稳定的各套餐曝光、订单、退款对账。
- 不能从平均搜索排名和 CTR 变化认定竞争对手抢走用户；国家和查询结构显著变化，需要固定查询×国家×设备再比较。
- 不能说网站速度已经合格或性能导致流失：GSC Core Web Vitals（更新至10/7）显示手机与桌面均“过去90天使用数据不足”。此次没有另跑性能实验。
- 不能说当前36→60题流程仍有旧bug：本次未复现该问题，现有统计也不能定位具体题目的异常。

**建议执行顺序：** 补正确的测量与错误定位 → 手机结果页紧凑套餐和明确免费入口 → 顶部分享/下载 → 报告样例与扩展题文案 → 根据实际结账数据再决定支付方式和定价优化。
